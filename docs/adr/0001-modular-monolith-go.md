# ADR 0001. Модульный монолит на Go с явными слоями

**Статус:** принято, 2026-10-10.

## Контекст
ТЗ допускает монолит «с явным разделением слоёв и слабо связанными модулями», микросервисы
приветствуются. Команда — один человек; прототип должен запускаться на обычной машине и
на недорогом VPS; жюри оценивает масштабируемость и возможность интеграции.

## Решение
Один процесс `cmd/api` на Go 1.25 с модулями `auth`, `candidates`, `testing`, `fsp`,
`needs`/`matching`, `invitations`, `vacancies`, `microtasks`, `admin`. Слои:
`transport/http` → `app` (use cases) → `domain`; `storage/postgres` и `infrastructure/*`
подключаются через интерфейсы. Mock ФСП ID/реестра — отдельный процесс `cmd/fspmock`
(у него другой жизненный цикл и владелец). Библиотеки `pkg/irt`, `pkg/itembank` без
зависимостей на приложение.

## Последствия
+ Простая сборка и запуск (один бинарник + PostgreSQL), низкое потребление памяти, быстрые тесты.
+ Модули можно вынести в сервисы без переписывания: границы — интерфейсы use case и таблицы по модулям.
− Нужно дисциплинированно держать границы модулей (линтер `depguard`/ревью).
