# ADR 0002. OpenAPI 3.1 генерируется из кода (huma)

**Статус:** принято, 2026-10-10.

## Контекст
ТЗ требует описать все методы через OpenAPI с запросами, ответами и кодами ошибок.
Варианты: spec-first (oapi-codegen), комментарии (swag, OpenAPI 2.0), code-first (huma).

## Решение
`huma v2` поверх `chi`: операции описываются Go-типами и `huma.Register`, спецификация
генерируется автоматически, валидация входа — по той же схеме, ошибки — `application/problem+json`
(RFC 9457). Документация доступна на `/api/v1/docs`, спецификация — `/api/v1/openapi.{json,yaml}`,
экспорт в `docs/api/openapi.yaml` на каждом релизе; клиент фронтенда генерируется из неё.

## Последствия
+ Спецификация никогда не расходится с кодом; один источник правды.
+ Валидация и единый формат ошибок бесплатно.
− Нестандартные ответы (стриминг, файлы) требуют отдельного описания; принимается.
