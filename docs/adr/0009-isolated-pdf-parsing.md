# ADR 0009. Разбор PDF от пользователя — в изолированном процессе

**Статус:** принято, 2026-10-11.

## Контекст
Кандидат загружает PDF-резюме; текст извлекается библиотекой `ledongthuc/pdf` (чистый Go).
Ревью безопасности показало, что у библиотеки есть циклы без защиты: цепочка `/Prev` таблиц
xref, ссылки `/Extends` потоков объектов, дерево страниц и поиск наследуемых ресурсов. Файл
размером около 1 КБ зацикливает разбор навсегда, а самоссылающийся поток объектов исчерпывает
стек — это фатальная ошибка Go, которая роняет весь процесс API, и `recover` её не ловит.
Кроме того, библиотека неверно декодировала широкие диапазоны ToUnicode (`<0000> <FFFF> <0000>`),
которые пишет fpdf/tFPDF, и раскладывала по строкам только текст, позиционированный через `Tm`.

## Решение
1. Извлечение текста выполняется в дочернем процессе того же бинарника (`fsp-api pdftext-worker`):
   PDF подаётся в stdin, текст читается из stdout. Тайм-аут 20 с, мягкий лимит кучи 512 МиБ,
   лимит стека 64 МиБ, `GOMAXPROCS=1`, минимальное окружение (секреты API процессу не передаются),
   не больше двух процессов одновременно. Тайм-аут или падение убивает только дочерний процесс;
   загрузка завершается черновиком с предупреждением «текст не извлечён».
2. В самом процессе разбора — собственный обход содержимого страниц: корректный разбор ToUnicode
   (своя реализация CMap), полное позиционирование текста (`Td`, `TD`, `T*`, `Tm`, `cm`, формы
   XObject), ширины глифов для восстановления пробелов, раскладка по строкам. Обход ограничен:
   глубина и число узлов дерева страниц, глубина форм, число операторов и время.
3. Интерфейс сервиса кандидатов — функция `Extract(ctx, data)`: в API — изолированный процесс,
   в тестах и утилитах — разбор в процессе.

## Последствия
+ Вредоносный PDF не останавливает API и не роняет процесс; это проверяет тест
  `TestIsolatedWorker` (файл с циклом `/Prev` обрывается по тайм-ауту).
+ PDF-профиль платформы и резюме из генераторов на fpdf/tFPDF читаются корректно (кириллица,
  строки, пробелы) — проверяется сквозным тестом `e2e/resume.spec.ts`.
− Запуск процесса добавляет десятки миллисекунд к загрузке; для разовой операции это допустимо.
− Жёсткий лимит памяти дочернего процесса задаётся средствами ОС при развёртывании.
